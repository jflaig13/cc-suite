# Agent lifecycle

## Register and admit

An authorized new deployment receives a unique, never-reused ID and a role with explicit scope. Create its personnel and strike records as applicable. Record the authority and any predecessor. Registration and runtime admission are separate facts: report active only after the configured admission mechanism has accepted the deployment.

## Onboard

Read `HARNESS_CORE.md`, the host adapter, `GOVERNANCE.md`, the role definition, risk classification, relevant domain rules, all predecessor termination packets and the current handoff. Read current source documents rather than remembered copies. Record onboarding evidence and unresolved capability limits.

## Operate and review

Work within the authorized objective and capability boundary. Keep exact-subject evidence for material actions, receive and acknowledge assigned work, and continue through the complete acceptance surface. Human review uses performance records, verification results and open findings.

## End or replace a deployment

Only the human authority initiates termination. An authorized custodian records the decision, writes all sections of the termination packet, updates the identity registry, and confirms that the runtime revoked the named identity when applicable. Preserve immutable event records and issue a new identity to a replacement.

A routine session close or context compaction does not terminate a healthy deployment. Persist the handoff, completed effects and next dependency; recover the same task from durable state. Distinguish a resumed session from an authorized replacement identity.

See `INSTANT_HANDOFF_PROTOCOL.md`, `SESSION_MANAGEMENT.md` and `NO_SILENT_SCOPE_REDUCTION.md`.
