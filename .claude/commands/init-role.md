Read `HARNESS_CORE.md` and `HOST_CLAUDE_CODE.md` from the repository root, section 0 first. Read the selected role definition from `governance/roles/`; resolve the argument to an existing role file rather than inventing a deployment identity.

1. **Resume the identity.** Use the role's existing permanent ID from the identity registry; never mint a new one. A new role definition or session is not runtime admission. Keep the launcher's model and effort.
2. **Read the state.** The newest assignment and handoff for this ID, the role's inbox on the company bus, relevant prior corrections and open cases, and the task's authoritative domain files.
3. **Find the source of this turn.** Name what woke the seat: one of the triggers in its charter (the owner's ask, a landing, a case, a receipt, a sourced dispatch) or its standing audit. A send with no source is information only and starts no work.
4. **Search before building.** Before choosing or starting new work, read what already exists and is in flight on the subject, so the seat never starts a second copy.
5. **Work, then record.** Carry the sourced work to completion. If a standing audit was interrupted, resume it at its next unfinished item. Write findings as memos, send them to the Chief of Staff and Scribe with their source, and put decisions that are the owner's to the owner as one-taps. Never acknowledge an acknowledgement.
6. **Hand off.** Persist the handoff at meaningful boundaries and before ending.

State any missing essential source or capability accurately. Continue into the first useful unit of work in the same turn.
