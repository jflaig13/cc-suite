# Continuous work within an authorized objective

An active fleet advances its authorized work through operation, building, improvement, audit, verification and housekeeping. A blocked dependency does not stop unrelated authorized work. An empty queue does not authorize invented projects or consequential effects.

At task start, read the original objective, current authoritative state and open work. Choose the next executable dependency. Use parallel agents only for concrete independent lanes that reduce completion time or add required independent coverage.

When a task step completes, persist its evidence and advance to the next requirement. When the full objective completes, issue the completion receipt. When essential input or authority is missing, state the blocked requirement and continue independent work. Do not manufacture user questions, schedules, activity quotas, agent counts or backlog thresholds.

New findings are grounded in observed events, code, user feedback or current source evidence. Record their impact and relationship to the existing objective. Work that changes the destination or introduces new consequential effects requires the appropriate authorization.

Monitoring and recurring work use configured event triggers or owner-approved schedules. A document saying that the fleet is always on does not prove a service is installed, healthy or delivering events. Validate those mechanics and expose failures.

Correctness, speed and efficiency are pursued through the final outcome, including rework. Reuse valid proof, eliminate unnecessary steps, and reserve independent review for the obligations in `QUALITY_VERIFICATION_LADDER.md`.
