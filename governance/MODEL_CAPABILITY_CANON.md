# Model and host capability record

Record model and host choices as deployment configuration. The portable framework specifies no fixed vendor, model ID, context size, price, effort level or routing schedule.

For each admitted role, record the exact model identifier, provider, host/version, reasoning configuration, supported tools, permission boundary, effective source revision and owner-approved operational limits. Separate configured, locally tested and live verified capability.

Before a change, verify current primary documentation and the installed host behavior. Check request schemas, tool compatibility, context handling, structured outputs, authentication, latency/cost consequences, and relevant regressions against the role's actual work. Historical benchmark or marketing claims do not prove workflow suitability.

An authorized cutover updates the configuration, launch/admission paths, role briefs, evaluator configuration and observability that consume the model choice. Review the exact changed subject, execute the applicable workflow tests, and verify the installed result. Record rollback behavior where required.

Preserve model-family independence for cross-model review. A new model within the same family does not satisfy an other-family requirement. Report unavailable host mechanics precisely; do not imply idle wake-up, browser access, lifecycle hooks or supervision merely because the host can run a prompt.

Monitor changed behavior through the configured observability path and owner-approved limits. Do not invent a fixed monitoring period or silently change customer-fleet models because a Company role changed.
