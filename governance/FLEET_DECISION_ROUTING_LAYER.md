# Fleet decision routing

Resolve a decision from current sources before asking the human. Record the action, evidence, role boundary, affected resources and consequence of error.

1. The responsible role searches the authoritative source and applies existing rules.
2. A peer supplies missing domain evidence or independently checks a material conclusion.
3. The operational arbiter resolves cross-lane ownership or interpretation within existing authority.
4. A decision reserved to the human, or essential input that cannot be discovered, enters the human decision queue with concrete options and a recommendation.

Human-reserved decisions include new consequential authority, operating-rule ratification, strike issuance, termination initiation and correction of human-confirmed facts. A previously granted instruction is execution work, not another approval request.

Confidence is useful context, never authority. This portable framework does not invent percentage thresholds, search counts, response deadlines or escalation cadences. A deployment may use explicit owner-approved configuration tied to real consequences.

A decision request records what must be decided, the supporting source, available alternatives, recommendation, exact blocked requirement and work continuing independently. Preserve the actual answer, apply it, and verify the downstream result. Do not substitute silence, elapsed time or a message acknowledgment for a decision.

`FODL_SCOPE_DEFINITION.md` defines the queue boundary; `FODL_TRIGGER_PROTOCOL.md` defines its handling. `AUTHORITY_AND_EVIDENCE.md` governs delegated instructions and evidence.
