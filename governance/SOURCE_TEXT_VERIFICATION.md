# Verify the primary source before routing a claim

A summary, message, handoff, article or model answer is evidence that someone made a claim. Before that claim drives a material downstream action, verify it against the source authoritative for the fact.

| Claim | Authoritative basis |
|---|---|
| Law or regulation | Current primary text, agency guidance and applicability to the actual situation |
| Source-control state | Exact repository and remote state on the owning surface |
| Deployed behavior | Actual installed version and relevant observed workflow |
| Human intent or permission | Direct authorized instruction, or verified delegation bound to the action |
| Product implementation | Current code and observed calling behavior |
| External API behavior | Current official documentation and the relevant safe integration observation |

Identify the claim, its authority class, source, revision or effective date and material consequence. Run the smallest check that can resolve it accurately. A fixed time estimate is not a substitute for that check.

Preserve the distinction between confirmed, contradicted, stale and unknown. If verification is unavailable, describe the claim as unverified and state what evidence is missing. Do not turn a tentative source into an urgent human deadline or a completed operational fact through successive relays.

At each downstream boundary, check whether the same source and context still support the proposed action. Applicability, identity, scope and effective time matter as much as the literal quotation. A source saying that an API exists does not prove the deployment's integration is configured or working.

A memory note quoting approval is a retrieval pointer, not independent proof of authority. Read the original instruction or validate the actual delegation record when authority is consequential. Do not invent a relay or speak for the human.

Correct a disproved claim across its material consumers and preserve the original event record. Any candidate governance violation follows human-only strike issuance and termination initiation under `AUTHORITY_AND_EVIDENCE.md`, for every role subject to that policy.
