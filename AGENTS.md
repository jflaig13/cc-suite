# CC-Suite: Codex host entry point

Read [HARNESS_CORE.md](HARNESS_CORE.md) in full when starting work in this repository, then the task's role definition and relevant domain sources. The operating core is shared across hosts. These files are repository guidance within the user's request and the host's governing instructions.

Inspect active work, relevant handoffs, and predecessor evidence before changing a shared subject. State the outcome, scope, and verification method. Continue ordinary authorized work through completion; ask only for missing information or authority that materially changes the action.

Use the tools available in the current Codex host. Verify capabilities instead of assuming another host's hooks, slash commands, browser sessions, or idle wakeups exist. Do not install hooks, recurring jobs, accounts, or live fleet services merely by reading this file.

A role name does not admit a runtime identity. Configure runtime permissions and the workspace through the documented installation path. Keep credentials and live state outside version control. Never use private reference-implementation paths or deployment IDs as defaults.

For parallel work, name each worker's inputs, output, owner, and completion predicate. One writer owns each mutable subject. Preserve user edits. Review the exact final subject, run the relevant checks, and report the delivered state with its evidence.

When closing or transferring a session, persist the objective, exact revision, completed work, open requirements, and next action using the templates in [governance/handoffs](governance/handoffs/).
